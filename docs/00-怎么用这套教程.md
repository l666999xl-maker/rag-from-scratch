# 00 · 怎么用这套教程

## 每一课的结构

```
这一课结束你会得到什么   ← 先看这个，知道终点
先理解这三件事           ← 概念，只讲必要的，不铺开
动手                     ← 一步步写代码
运行                     ← 命令 + 预期输出
如果报错                 ← 常见错误对照
动手改一处               ← 改一个参数，看结果怎么变
自测                     ← 不看文档回答
```

---

## 三条使用建议

### 1. 一次只做一课

不要一口气看完。看完一课、跑通、改一处，再进入下一课。

**"跑通了"和"懂了"是两件事。** "动手改一处"就是用来检验后者的。

### 2. 代码先抄，再关掉文档重写

第一遍照着抄没问题——你不是在练打字。
但抄完要做一件事：**关掉文档，凭记忆把关键的那 10~20 行写一遍**。

写不出来，说明你只是抄了，没懂。

### 3. 报错先自己看 3 分钟

本项目的报错基本都能自己读懂。先看**最后一行**（异常类型和消息），
再看**倒数第二行**（出错的文件和行号）。

实在卡住，把这三样发出来：

1. 完整的报错（不要只发最后一行）
2. 你改的那段代码
3. 你以为应该发生什么

## 关于参考代码

`src/` 下已经有一份能跑的完整实现。

**建议的顺序是**：

1. 先读教程，理解每一步在干什么
2. 自己照着写一遍（可以新建 `.py` 文件，也可以直接改现有的）
3. 跑不通时，对照 `src/` 里的参考实现找差异
4. 跑通之后，关掉文档，把关键逻辑复述一遍

**不要一上来就运行 `src/` 里的代码然后跳过教程**——那样你只是看了一个项目，没学会。

## 你需要的最低基础

- 会用 Python 写函数、读写文件、装包
- 知道什么是 HTTP 请求（会调 API 就行）
- 不需要会机器学习，不需要会前端

## 每一步都能单独停下来

这 8 步不是必须连着的：

- 只做 1~4 步，你得到一个**关键词检索系统**
- 做到 6 步，你得到一个**混合检索系统**
- 做到 7 步，你得到**能回答问题的 RAG**
- 做到 8 步，你得到**能证明自己好坏的 RAG**

如果时间不够，**做到第 7 步就已经可以写进简历了**。
