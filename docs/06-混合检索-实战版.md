## 这一课结束你会得到什么

- 一个把 BM25 和向量检索融合起来的检索器

| 检索方式 | Top-1 | Top-3 |
|---|---|---|
| BM25 | 11 / 14 | 12 / 14 |
| 向量 | 13 / 14 | 14 / 14 |
| **混合（RRF）** | **14 / 14** | **14 / 14** |

- 一个必须承认的事实：混合检索的权重是在 14 条问题上调的，**不是普适值**

## 一、为什么不能把两路分数直接相加

看同一句话在两个系统里的分数：

```
查询：葡萄柚和降压药能一起吃吗

BM25 第 1 名：51.134
向量第 1 名：0.748
```

`51.134` 和 `0.748` 不是同一种东西：

- BM25 的分数没有上界，随语料规模、词频、长度变化
- 余弦相似度固定在 -1 ~ 1 之间

直接相加、加权平均、归一化后相加，都会引入一堆需要解释的参数，
而且换一份语料就失效。

**RRF（Reciprocal Rank Fusion）换了一个思路：不看分数，只排名次。**

---

## 二、RRF 在算什么

公式：

```
RRF(文档) = Σ  权重 / (K + 名次)
             每一路
```

- 名次从 1 开始
- `K` 是平滑常数。K 越小，前几名的话语权越大
- 权重控制"这一路有多可信"

举例。查询"药和水果能不能一起吃"：

| 文档 | BM25 名次 | 向量名次 | RRF 分数（权重 1 : 3，K=10） |
|---|---|---|---|
| 34-13 葡萄柚 | 没进前 10 | 1 | `3 / (10+1)` = **0.2727** |
| 2-27 多吃果蔬 | 1 | 7 | `1/(10+1) + 3/(10+7)` = **0.2674** |

34-13 赢，但只赢了 0.0053。

这说明两件事：

1. RRF 能融合两路的信息
2. **融合结果对权重很敏感**——换一组权重，第一名可能就翻了

### 为什么名次比分数稳

假设某一路给了一个"非常自信但错了"的第 1 名。
在分数相加里，它的巨大分数会压过另一路的正确答案；
在 RRF 里，它最多贡献 `权重 / (K+1)`，另一路的第 1 名也是同样的量级。
两路都有机会说话，而不是被一个异常分数绑架。

## 三、代码怎么读

打开 `src/hybrid_search.py`。

### 1. 常量：K、权重、候选深度

```python
RRF_K = 10
BM25_WEIGHT = 1.0
VECTOR_WEIGHT = 3.0
CANDIDATES = 10
```

- `CANDIDATES=10`：每一路先取前 10 名进入融合，最后再取前 5
- `RRF_K=10`：这份数据上，K=60 会把名次差距压得太扁，见第六节
- `VECTOR_WEIGHT=3.0`：向量这一路的权重是 BM25 的 3 倍

**权重为什么是 1 : 3？**
因为 BM25 会"自信地错"：问"药和水果能不能一起吃"，它第 1 名给了无关条目。
把 BM25 的权重压低，让向量的正确结果浮上来。

但这是**在这 14 条问题上试出来的**，不是定理。第 8 课会用更大的评测集重调。

### 2. 去重键：先把"同一条建议"认出来

```python
def chunk_key(item: dict) -> tuple:
    if item["kind"] == "tip":
        return ("tip", item["section_no"], item["item_no"])
    return ("chunk", item["id"])
```

第 3 课把 138 条长建议拆成了 2–3 块。
如果 BM25 命中第 1 块、向量命中第 2 块，它们其实是同一条建议。
用 `(节号, 条号)` 作为键，融合时才能把它们合并成一条。

### 3. 融合

```python
for rank, item in enumerate(bm25_results, 1):
    key = chunk_key(item)
    scores[key] = scores.get(key, 0.0) + BM25_WEIGHT / (RRF_K + rank)
    bm25_rank[key] = rank
    items.setdefault(key, item)

for rank, item in enumerate(vector_results, 1):
    key = chunk_key(item)
    scores[key] = scores.get(key, 0.0) + VECTOR_WEIGHT / (RRF_K + rank)
    vector_rank[key] = rank
    items.setdefault(key, item)
```

用 `setdefault` 而不是直接覆盖：同一个文档两路都有时，保留先到的文本，
但两个名次都记下来，展示时能看到"BM25 #1 / 向量 #2"。

### 4. 结果里保留两路的名次

```python
item["score"] = round(scores[key], 4)      # RRF 融合分
item["bm25_rank"] = bm25_rank.get(key)
item["vector_rank"] = vector_rank.get(key)
```

**这是混合检索最有用的调试信息。**
某条结果为什么排第一？看它是不是两路都靠前。
某条为什么没进来？看它是不是只在一路里排第 30。

### 5. 输出

```
1. [第 19 节第 6 条 | 第 382 页] RRF 0.3409
   BM25 #1   向量 #2
```

`RRF 0.3409` 是融合分，只用来排序，不要和 BM25、余弦分数比较。

## 五、14 条问题的三路对照

| 组 | 题数 | BM25 Top-1 / Top-3 | 向量 Top-1 / Top-3 | 混合 Top-1 / Top-3 |
|---|---|---|---|---|
| 词汇重合 | 6 | 6 / 6 | 5 / 6 | **6 / 6** |
| 换个说法 | 6 | 5 / 6 | 6 / 6 | **6 / 6** |
| 语义（无共同关键词） | 2 | 0 / 0 | 2 / 2 | **2 / 2** |
| **合计** | **14** | **11 / 12** | **13 / 14** | **14 / 14** |

怎么读这张表：

1. **混合把两路的强项都保住了**：词汇组回到 6/6，换说法组保持 6/6，语义组 2/2。
2. **Top-3 上向量已经是 14/14**，混合没有提高召回，它提高的是 **Top-1 的排序质量**。
   对 RAG 来说这很重要：第 7 课只把前几条塞进 prompt，排第一的那条权重最大。
3. **BM25 在语义组 0/2**：这不是 BM25 写坏了，是它只会数词。

注意样本量：14 条问题只够验证"方向对不对"，不够证明"混合一定更好"。
第 8 课要扩到 30 条以上，并且把"可接受的邻近条目"也算进去。

## 六、权重实验：为什么是 1 : 3

固定 `RRF_K=10`、`CANDIDATES=10`，只改权重，结果：

| BM25 : 向量 | Top-1 合计 | 词汇 / 换说法 / 语义 |
|---|---|---|
| 1 : 1（朴素 RRF） | 12 / 14 | 6 / 6 / **0** |
| **1 : 3（当前）** | **14 / 14** | 6 / 6 / 2 |
| 0 : 1（只用向量） | 13 / 14 | 5 / 6 / 2 |
| 1 : 10 | 14 / 14 | 6 / 6 / 2 |

再看 `RRF_K`：

| 配置 | Top-1 合计 | 说明 |
|---|---|---|
| K=10，1 : 3 | **14 / 14** | 当前 |
| K=60，1 : 3 | 13 / 14 | 名次被压平，语义组只对 1 条 |

### 朴素 RRF 为什么在语义题上翻车

以"药和水果能不能一起吃"为例，K=10、1 : 1：

```
2-27（错误）  BM25 #1, 向量 #7  → 1/11 + 1/17 = 0.1497
34-13（正确） BM25 未进前10, 向量 #1 → 1/11      = 0.0909
```

BM25 的"自信错误"在第 1 名，向量虽然把正确答案排第 1，但只有一份票，
压不过 BM25 在另一路里的第 7 名贡献。加权到 1 : 3 后：

```
34-13：3/11 = 0.2727
2-27 ：1/11 + 3/17 = 0.2674
```

正确结果才以 0.0053 的微弱优势翻上来。

**这条要记住**：加权 RRF 不是"更高级所以更好"，它是**用权重表达"我更信谁"**。
权重是靠评测集调出来的，不是拍脑袋。第 8 课会把这件事做得更严谨。

## 七、四个实验（必须动手）

### 实验 1：把权重改回 1 : 1

```python
VECTOR_WEIGHT = 1.0
```

重跑 14 条，重点看这两条：

```powershell
.\.venv\Scripts\python.exe src\hybrid_search.py "药和水果能不能一起吃"
.\.venv\Scripts\python.exe src\hybrid_search.py "喝酒之后吃消炎药有事吗"
```

**预期**：两条的正确答案都掉出第 1 名，总成绩 12/14。
这就是"朴素 RRF 不够"的现场证据。

### 实验 2：只用一路

- `BM25_WEIGHT = 0`：只剩向量，词汇组掉到 5/6（"赔偿金"那条）
- `VECTOR_WEIGHT = 0`：只剩 BM25，语义组掉到 0/2

**要体会**：混合的价值不是"两路都还行"，是**两路的失败模式不一样**。

### 实验 3：`RRF_K` 改 60

```python
RRF_K = 60
```

**预期**：13/14，语义组只对 1 条。
K 越大，第 1 名和第 10 名的贡献越接近，融合越"民主"，也越容易被噪声影响。

### 实验 4：`CANDIDATES` 改 3 / 5 / 20

**实测**：

| 每路候选数 | Top-1 合计 |
|---|---|
| 3 | 13 / 14 |
| 5 | 14 / 14 |
| 10 | 14 / 14 |
| 20 | 14 / 14 |

候选太少（3）时，正确答案可能根本没进融合池；10 已经够用，
再加大只是多算一些注定进不了前 5 的条目。

## 八、已知限制

1. **权重是在 14 条问题上调的**。样本太小，1 : 3 不是普适最优。
   第 8 课扩到 30+ 条，用 Recall@3 / MRR 重调。
2. **非条目的块会抢位置**。附录长文（essay）和节导语（intro）经常排在第 2、3 名。
   它们不是错的，但对"具体该怎么做"这类问题，条目块通常更有用。
   可以试：给 `kind=="tip"` 加一个小的固定加分，或者在 prompt 里优先放 tip。
3. **RRF 丢掉分数差的信息**。如果向量第 1 名 0.75、第 2 名 0.45（断层很大），
   RRF 仍然只按名次给分，不会额外奖励这种"非常确定"。
   这是 RRF 的取舍：稳，但不利用置信度。
4. **依赖 embedding 接口**。每次查询 0.3–0.4 秒；接口挂了，混合检索也跟着挂。
   BM25 单路是纯本地的。
5. **融合分不能跨查询比较**。0.34 和 0.27 只在同一次查询里有意义。

## 九、下一步

第 7 课：把混合检索的前几条塞进 prompt，让模型回答并标注出处。

做法：

- 每条上下文前面加 `[第 X 节第 Y 条 | 第 Z 页]`
- prompt 里明确要求"只能依据资料回答，找不到就说找不到"
- 回答末尾列出用到的 `section` + `item_no`，需要时再附 `refs`

第 8 课：把现在的 14 条问题扩成正式评测集，给每条标 1–2 个可接受答案，
然后比较 BM25 / 向量 / 混合的 Recall@3，并重调权重。
