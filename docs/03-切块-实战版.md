## 一、先把数据看清（这一步不能跳）

切块切得烂，九成不是代码技巧问题，是**没有先看清数据的结构**。
写任何规则之前，先回答三个问题：

1. 这份 PDF 的一行，是"一行字"还是"一个段落"？
2. 这份文档真正的语义单元是什么？
3. 哪些内容是页眉页脚目录这种"每页都有、但没有检索价值"的噪声？

### 这份语料的 6 个事实

我用 10 行 Python 统计出来的，你也可以自己跑：

```powershell
.\.venv\Scripts\python.exe -c "import json; p=json.load(open('build/pages.json',encoding='utf-8')); print(len(p), sum(len(x['text']) for x in p))"
```

| 事实 | 数字 | 对切块的影响 |
|---|---|---|
| 页数 | 589 页 | 不能按页独立切，条目会跨页 |
| 总字数 | 1,153,868 字 | 平均每页约 1959 字 |
| 非空行数 | 25,133 行 | 平均每行约 46 字，说明是**硬折行** |
| 有页眉的页 | 540 页 | 每页第一行是 `高性价比人生指南 <节名>` |
| 页脚页码 | 586 处 | 形如 `177 / 586` |
| 编号建议 | 767 条 | 正文有 34 节，每节的条目重新从 1 编号 |

### 这本书真正的结构

随手打开第 180 页，原文长这样（`pages.json` 里是带换行的）：

```
14. 求职别只投简历，用系统方法：学技巧、定目标、找人帮
• 成本：不花钱。每天要花 1 到 2 小时，连着做上几周。付费课程可以不报，用公共就业服务机构的
免费职业指导代替。难在没人盯着的时候天天坚持，还要主动开口找人帮忙。
• 说人话：参加过求职辅导的人，找到工作的几率是没参加的人的 2.67 倍。管用的是这几样：学具体
的求职技巧，把自己讲清楚，定明确目标，主动出击，开口找人帮忙。
• 收益：……
• 证据等级：B
‣ 财政部、人力资源社会保障部 (2023 修订). 就业补助资金管理办法……
• 备注：……
```

拆开看，一条建议固定由这几样组成：

```
条目标题          14. 求职别只投简历……
  • 成本          花掉什么
  • 说人话        一句话结论 + 数字
  • 收益          证据和数据
  • 证据等级      A / B / C
  ‣ 来源          参考文献（大量网址）
  • 备注          补充说明
```

**结论：这本书的语义单元是"一条建议"，不是"500 字"。**
用户问"求职辅导有用吗"，理想情况是**正好命中第 14 条这一整块**，而不是命中半条。

### 你原来的代码错在哪

先把旧代码的三处关键逻辑贴出来：

```python
# 1. 每一行都被当成一个段落
paragraphs = [p.strip() for p in text.split("\n") if p.strip()]

# 2. 按字数攒，攒到 500 就吐出去
if len(buffer) + len(para) <= size:
    buffer += para + "\n"
else:
    chunks.append(buffer.strip())
    # 3. 从上一块末尾硬切 70 字当重叠
    overlap = buffer[-OVERLAP_SIZE:] if len(buffer) > OVERLAP_SIZE else buffer
    buffer = overlap + para + "\n"
```

对照这份数据，三处全部踩中：

| 旧逻辑 | 为什么在这份数据上会坏 | 真实后果 |
|---|---|---|
| 按页循环、每页独立切 | 一条建议经常跨两页（如第 19 节第 19 条，p389–390） | 同一条被拆到两个文件页里，语义断裂 |
| 把每个换行当段落 | PDF 每行约 46 字，是排版折行，不是段落 | `buffer` 攒 12 行就断，断点必然落在句子中间 |
| `buffer[-70:]` 当重叠 | 这是"从任意字符位置切 70 字"，不是从句子边界 | 新块开头是半个句子 |

旧产物里的真实样本：

```
HowToLiveBetter.pdf#180#5
"到 2 小时，连着做上几周。付费课程可以不报……"

HowToLiveBetter.pdf#98#5
"管的是头痛，痛经吃药的天数也远到不了。……"

HowToLiveBetter.pdf#425#1
"高性价比人生指南 23. 学什么技能划算
‣ 全国人大常委会 (2018). 义务教育法……"     ← 页眉混进来了

HowToLiveBetter.pdf#466#4
"……开口找人帮忙。\n177 / 586"              ← 页码混进来了
```

还有两个隐藏问题：

- **500 字和语义单元无关**：去掉参考文献后，一条建议的中位数是 **711 字**，p90 是 1252 字。用 500 字去切，等于把大半条建议腰斩。
- **每节最后一条会吞掉下一节导语**：这是我在重写时发现的。旧逻辑只在遇到下一个条目标题时才收尾，换节时没有收尾，于是第 18 节第 7 条的正文里出现了第 19 节的导语（"离职和被裁：被裁先算清 N……"）。**换节必须强制 flush**，这是边界处理问题。

## 二、正确切法的三条原则

### 原则 1：切块单位 = 语义单元

先问："这份文档里，最小的、单独拿出来仍然完整的意思是什么？"

- 政策文件：一条法条
- 这本书：一条建议
- 聊天记录：一条消息
- 如果是没有固定结构的小说：一个自然段

**不要从"多少字"开始设计，先从"什么意思算完整"开始设计。**

### 原则 2：先还原，再切分

PDF 给你的不是段落，是"排版行"。顺序必须是：

```
PDF 行 → 还原成段落 → 按语义边界切块
```

不能跳过中间那步。还原的核心判断是：

- 上一行结尾有没有句末标点（。！？；）
- 这一行是不是新的小标题 / bullet / 条目标题
- 都不是 → 这一行是上一行的折行，接回去

### 原则 3：只在边界切，不用重叠

重叠是给"无结构长文本"兜底的手段，代价是块里混入无关内容、块首半句话。
只要你在正确的语义边界切，就不需要重叠。

**这本书不需要 overlap。**

## 三、新代码怎么读

打开 `src/chunk_text.py`，从上往下读。下面只挑关键部分讲。

### 1. 常量：上限从 500 改成 1000

```python
MAX_CHUNK_CHARS = 1000   # 单块上限
MIN_CHUNK_CHARS = 60     # 过滤前言里的碎片
MIN_PART_CHARS = 250     # 拆条时，末尾不足 250 字的分段并回前一块
```

为什么是 1000？

- 一条建议的正文（去掉参考文献后）中位数 711 字
- 1000 字能让 631 条建议**一条一块、不拆**
- 剩下 138 条超长的，在段落边界拆，每块都重复条目标题

不是拍脑袋：这个数在第七节的实验表里可以调，调完用检索效果验证。

### 2. `content_lines`：先把噪声拿掉

```python
if line.startswith(HEADER_PREFIX):      # 页眉
    continue
if PAGE_NO_RE.match(line):              # 页码 177 / 586
    continue
if TOC_LINE_RE.search(line):            # 目录行：标题 …… 页码
    continue
if line == section:                     # 节标题单独一行
    continue
```

顺序很重要：**先清洗、再还原、最后切块**。
如果先切块再清洗，页码已经被接进句子里，就删不掉了。

### 3. `join_wrapped`：把折行接回去

```python
def join_wrapped(prev: str, line: str) -> str:
    if is_ascii_alnum(prev[-1]) and is_ascii_alnum(line[0]) and not has_open_url(prev):
        return prev + " " + line
    return prev + line
```

三种情况：

| 情况 | 处理 | 例子 |
|---|---|---|
| 中文接中文 | 直接拼 | `"结果容易被"` + `"别的因素带偏"` |
| 英文接英文 | 补一个空格 | `"Among"` + `"killed"` → `"Among killed"` |
| 上一行是没写完的网址 | 不补空格 | `"https://doi.or"` + `"g/10.1186"` |

`has_open_url` 就是判断"行尾是不是一个没闭合的 URL"。不处理这个，网址会被空格劈成两半。

### 4. `assign_sections`：给每页标上它属于哪一节

有页眉的页直接读页眉。没有页眉的页（新一节的第一页）看前后：

```python
if next_s and next_s != prev_s:
    sections[i] = next_s     # 前后节名不同，说明这一页是新一节的开头
else:
    sections[i] = prev_s     # 否则沿用上一节
```

没有这一步，你就不知道"第 16 页那堆文字属于第 1 节"，也没法处理换节边界。

### 5. `extract_tips`：怎么认出"条目标题"

最容易想到的规则是"行首是数字加点"。但这份数据里至少有三种假阳性：

- 目录行：`14. 求职别只投简历 ........ 180`
- 参考文献：`2021. China CDC Weekly：「……`
- 条目内部的编号列表

新代码加了一个很便宜但很有效的条件：**编号必须连续**。

```python
number = int(match.group(1)) if match else -1
is_tip_title = (
    match is not None
    and number == expected.get(section, 1)   # 必须是本节的下一条
    and "中文" in 标题
    and not 标题.endswith(("。", "；"))
)
```

- 第 5 节的条号是 1,2,3……13
- 上一行刚处理完第 7 条，`expected[section]` 就是 8
- 只有"8. "开头的行才可能是下一条
- 目录、文献年份、内部列表的编号几乎不可能刚好接上

这一条规则让 767 条建议被**准确识别**，不多不少。跑完会打印自检：如果哪一节漏了条号，会直接告诉你是哪几条。

### 6. 换节必须 flush

这是重写时抓到的真 bug：

```python
if current and current["section"] != section:
    flush()
```

没有这三行，第 18 节最后一条会把第 19 节的导语吞进自己的正文。
**所有"按边界切"的代码，都要专门处理"边界恰好换类型"的情况。**

### 7. 参考文献移出正文

```python
def is_reference(paragraph: str) -> bool:
    return bool((paragraph.startswith("‣") or SOURCE_RE.match(paragraph))
                and URL_RE.search(paragraph))
```

为什么？

- 参考文献平均 542 字，正文平均 779 字，几乎占一半
- 里面全是 `https://...`，对向量和 BM25 都是强噪声
- 但它不能丢：第 7 步要拿它做引用

所以：**正文 `text` 只放可检索的内容，参考文献放进 `refs` 字段**。

注意判断条件带了 `URL_RE`：`‣` 开头的段落里也有纯文字的证据说明（比如"丹麦一项研究……"），那些是正文，不能移走。

### 8. 超长条目怎么拆

```python
groups = pack_paragraphs(content, MAX_CHUNK_CHARS)
groups = merge_short_tails(groups)
```

- `pack_paragraphs`：按段落顺序装，装不下就开新块，**段落本身绝对不拆**
- 只有单个段落自己就超过 1000 字时，才按句号切（`split_long_paragraph`）
- `merge_short_tails`：末尾不足 250 字的分段并回前一块，避免出现"只剩一句备注"的碎片

拆出来的每一块都长这样，标题重复：

```
【5. 不要浪费钱】
14. 喝烧开的自来水，不常年订饮水机用的桶装水、买瓶装水
• 成本：……
```

标题重复是故意的：用户搜"桶装水"，命中第二段时，模型仍然知道这段在讲哪一条。

### 9. 前言 / 导语 / 附录

- **前言**（p1–12）：没有"条"，按段落攒到 1000 字一块
- **各节导语**（每节开头的"这一节算的是……"）：单独成块，`kind="intro"`
- **各节简介**（p12–15）：是目录型摘要，和正文重复，且表格提取乱序，**跳过**
- **附录长文**（p560–589）：按段落攒，`kind="essay"`

### 10. 每块带哪些字段

```json
{
 "id": "HowToLiveBetter.pdf#p117#s05-14-1",
 "source": "HowToLiveBetter.pdf",
 "page": 117,
 "page_end": 117,
 "kind": "tip",
 "section": "5. 不要浪费钱",
 "section_no": 5,
 "item_no": 14,
 "title": "14. 喝烧开的自来水……",
 "text": "【5. 不要浪费钱】\n14. 喝烧开的自来水……\n• 成本：……",
 "refs": ["‣ 北京市发展和改革委员会. 居民用水价格表. https://..."]
}
```

后面的第 4–8 课只需要 `id`、`text`、`page`、`section`、`title`、`refs` 这几个字段。

## 五、验收：不要只看块数

块数好看不代表切得好。用下面 5 个检查，顺序从硬指标到人工判断。

### 检查 1：条数对不对

```python
import json
c = json.load(open("build/chunks.json", encoding="utf-8"))
print(len({(x["section_no"], x["item_no"]) for x in c if x["kind"] == "tip"}))
# 767
```

### 检查 2：每块是不是以【节名】开头

```python
print(sum(1 for x in c if not x["text"].startswith("【")))   # 0
```

### 检查 3：有没有页码 / 页眉残留

```python
import re
print(sum(1 for x in c if any(
    re.fullmatch(r"\d+\s*/\s*\d+", ln.strip()) or ln.startswith("高性价比人生指南")
    for ln in x["text"].splitlines()
)))   # 0
```

### 检查 4：抽 10 块人工读

随机抽 10 块，只看两个地方：

- 第一行之后，是不是完整的标题 + 完整句子？
- 最后一行，是不是句号 / 完整的备注？

如果开头是"到 2 小时……"这种，说明标题丢了；如果结尾突然断，说明拆块位置不对。

### 检查 5：refs 有没有内容

```python
print(sum(1 for x in c if x["kind"] == "tip" and x["refs"]), "/", 
      sum(1 for x in c if x["kind"] == "tip"))
# 911 / 918
```

有 12 块没有 refs，是正常的：那几条原文就没有带网址的来源。

## 六、一个必须体会到的点：切块长度是权衡，不是标准答案

把 `MAX_CHUNK_CHARS` 改掉，重跑，记录数字。下面是我实测的四组（最终代码）：

| MAX_CHUNK_CHARS | 总块数 | 正文条目块 | 被拆的条数 | 中位长度 | 最长 |
|---|---|---|---|---|---|
| 600 | 1450 | 1297 | 347 | 521 | 1179 |
| **1000（当前）** | **1017** | **918** | **138** | **716** | **1262** |
| 1500 | 865 | 792 | 25 | 758 | 1810 |
| 2500 | 826 | 768 | 1 | 761 | 2632 |

怎么看这张表：

- **600**：一条建议经常被拆成 2–3 块。检索更"尖"，但模型拿到的信息不完整。
- **1000**：大部分条目不拆，少数长条目拆两块。**推荐起点。**
- **2500**：几乎一条一块，检索粒度最粗，但每次问答塞给模型的字更多。

不要在没做评测前就说哪个更好。第 8 课会用 Recall@3 和回答质量来比较。
你现在要做的，是知道"这个参数控制什么"。

## 七、已知问题（留作练习）

### 1. 表格页仍然提取乱序

前言 p4–5、附录 p565、p572 是表格。`pdfplumber.extract_text()` 按坐标从上往下读，
多列表格会被拼成：

```
这本书想回答的问题问题 去哪看几乎不花钱，就能明显降低早死概率的事有哪些？
1. 不要早死抽烟、喝酒、久坐、熬夜到底折寿多少，烟和酒具 2. 不要慢慢死体怎么戒……
```

能看出"问题"和"答案"两列被交错拼在一起了。

**练习**：在第 2 步的 `load_pdf.py` 里用 `page.extract_tables()` 把表格单独提取；
或者给这些页加一个"跳过"名单。先判断这些表对检索有没有价值，再决定。

### 2. 附录里还有一些没编号的短标题

`一、先把问题拆开` 已经能识别了；`头一周`、`三条路` 这种还不行，会粘在正文上。

**练习**：给 `looks_like_heading` 加一条规则，但要小心——表格里的短行也会被误判。
更稳的做法是在第 2 步用字号信息（`page.chars` 里的 `size`）判断标题，而不是猜文本。

### 3. 各节简介被整体跳过

`SKIP_SECTIONS = {"各节简介"}`。理由：它是目录型摘要，和正文重复，而且表格提取乱序。
如果你想把"每节有哪些条"也做成可检索的，把它从集合里删掉，先修表格提取。

### 4. `refs` 下游怎么用

现在 `refs` 只是存着。第 7 课生成回答时可以：

- 把 `refs` 拼进 prompt 的"出处"部分
- 或者只给用户显示 `section` + `item_no` + `page`，`refs` 放后台

两种都行，但要先决定，别到时候又改 schema。

## 八、自测

不看文档回答：

1. 为什么不能把 PDF 的每一行当成一个段落？这份 PDF 每行大约多少字？
2. 一条建议的正文中位数是多少字？为什么 `MAX_CHUNK_CHARS=500` 会切坏？
3. "编号必须连续"这个条件，排除了哪三类假阳性？
4. 为什么换节时要 `flush()`？不写会出现什么具体症状？
5. 参考文献为什么要移出 `text`？移出之后，答案里的引用从哪里来？
6. 为什么这本书不需要 overlap？
7. 切块长度是越大越好还是越小越好？用什么来证明你的选择？

---

## 九、这一课真正要带走的东西

不是"这份文档该切 1000 字"，而是这套顺序：

```
1. 统计：页数、行数、平均行长、页眉页脚、编号行数量
2. 找语义单元：这本书是"一条建议"
3. 定边界：编号连续性 + bullet + 句末标点
4. 写规则：清洗 → 还原 → 切分 → 超长才拆
5. 自检：条数、噪声残留、长度分布、随机抽样
6. 调参：用检索评测决定，而不是凭感觉
```

下一课（BM25）会把 `chunks.json` 读进内存建索引。
到时候你会第一次真正验证：**切块切得好，检索才会准。**

---

## 十、接下来每一步做什么（按当前数据）

现有 `docs/04` ~ `docs/09` 的示例还是旧的医院 PDF，但**方法完全适用**。
做的时候把示例问题换成这本书的问题，把数据源固定成现在这份 `chunks.json`。

| 步骤 | 你要做的事 | 用这份数据的验收标准 |
|---|---|---|
| 第 4 课 BM25 | `jieba` 分词 + `rank_bm25`，读 `chunks.json` 的 `text` | 问"桶装水比自来水贵多少"能命中第 5 节第 14 条 |
| 第 5 课 向量 | DashScope embedding，分批 20 条，存 `build/vectors.npy` | 问"被公司裁了先做什么"能命中第 19 节相关条目 |
| 第 6 课 混合 | BM25 + 向量，用 RRF 按名次融合 | 精确词（如"葡萄柚"）和口语问法都能命中 |
| 第 7 课 生成 | 把命中块的 `text` 拼进 prompt，用 `section` + `item_no` 标注出处 | 回答里能写出"第 5 节第 14 条"，需要时能列出 `refs` |
| 第 8 课 评测 | 自己写 20 条问题，标好正确答案的 `(section_no, item_no)` | 分别测 BM25 / 向量 / 混合的 Recall@3 |
| 第 9 课 收尾 | 写 README、录一段演示、准备面试讲法 | 能说清"为什么一条建议一块、为什么 1000 字" |

第 8 课是回头验证这一课的地方：

- 如果评测发现"总是召回半条"，说明 `MAX_CHUNK_CHARS` 太小或切点不对
- 如果发现"召回块里一半是网址"，检查 `refs` 有没有漏移
- 如果发现"跨页的条目答不全"，检查 `assign_sections` 和跨页拼接

**切块好不好，最终不是看块数，是看 Recall@3 和回答能不能用。**
