## 先理解三件事

### 1. 为什么必须有评测

没有评测，你所有关于"这个方案更好"的判断都只是感觉。

有了评测，你才能说：

> "混合检索的 Recall@3 是 100%，向量是 92%——因为评测集里有口语化查询，
> 向量也会漏。"

而且评测能暴露你自己想不到的问题。第 7 课的引用格式 bug，
就是在跑评测时暴露的。

### 2. 客观指标 vs 主观指标

| | 客观 | 主观（LLM 打分） |
|---|---|---|
| 例子 | 召回率、引用是否有效、拒答与否 | 回答是否流畅、是否有帮助 |
| 可复现 | 是 | 否，会波动 |
| 成本 | 低 | 每条都要调一次模型 |

**原则：能做成客观指标的就做成客观的。**
LLM 打分只用在最后那一层。

### 3. 评测集要有区分度

如果所有用例都轻松通过，这个评测集什么也证明不了。

本项目刻意放了两类难例：

- **口语化改写**："每个月工资里扣多少医保"（原文是"缴费基数 8%"）
- **应该拒答**："你们医院停车费多少钱"（语料里没有）

## 动手

把 `src/step8_eval.py` 换成下面这段。

### 第一步：评测集

```python
RETRIEVAL_CASES = [
    {"q": "医保缴费基数的上限是多少", "sources": ["sz-medical-insurance-2023.pdf"]},
    {"q": "职工医保一档在三级医院的报销比例", "sources": ["sz-longhua-cross-region.pdf"]},
    {"q": "异地就医备案有哪几种类型", "sources": ["sz-longhua-cross-region.pdf"]},
    {"q": "门诊预约最多可以提前多少天", "sources": ["lyg-appointment-cancel.pdf"]},
    {"q": "宁阳县葛石镇中心卫生院的预约电话是多少", "sources": ["ningyang-visit-notice.pdf"]},
    {"q": "2A 二区有哪些门诊", "sources": ["lyg-appointment-cancel.pdf"]},
    {"q": "学生医保的年度支付限额", "sources": ["sysu-student-insurance.pdf"]},
    {"q": "生育保险待遇包括哪些", "sources": ["sz-longhua-cross-region.pdf"]},
    {"q": "我退休后去外地跟孩子住，看病怎么报销", "sources": ["sz-longhua-cross-region.pdf"]},
    {"q": "预约了不去会有什么后果", "sources": ["lyg-appointment-cancel.pdf", "ningyang-visit-notice.pdf"]},
    {"q": "每个月工资里扣多少医保", "sources": ["sz-medical-insurance-2023.pdf"]},
    {"q": "看病自己先掏多少钱才开始报销", "sources": ["sz-medical-insurance-2023.pdf", "sysu-student-insurance.pdf"]},
]

REFUSAL_CASES = [
    "你们医院停车费多少钱一小时",
    "张建国医生的手机号是多少",
]
```

**每条用例包含两个东西**：问题 + 正确答案在哪些文件里。

`sources` 是列表，因为有些问题在多个文件里都有答案，命中任一即可。

### 第二步：召回率

```python
def recall_at_3(search_fn) -> float:
    hit = 0
    for case in RETRIEVAL_CASES:
        results = search_fn(case["q"], 3)
        got = {item["source"] for item in results}
        if got & set(case["sources"]):
            hit += 1
    return hit / len(RETRIEVAL_CASES)
```

**`got & set(...)`** 是集合交集：返回结果里只要有一份是期望文件，就算命中。

**Recall@3 的含义**：前 3 条结果里有没有正确答案。
它不关心排第几，只关心"有没有"。

### 第三步：跑三种检索

```python
bm25 = load_bm25()
vector = load_vector()

methods = [
    ("BM25", lambda q, k: bm25.search(q, k)),
    ("向量", lambda q, k: vector.search(q, k)),
    ("混合 RRF", lambda q, k: hybrid_search(q, k)),
]
for name, fn in methods:
    print(f"  {name:<10} {recall_at_3(fn):.0%}")
```

### 第四步：引用与拒答

```python
citation_ok = 0
for case in RETRIEVAL_CASES[:6]:
    result = ask(case["q"])
    check = result["check"]
    if check["passed"] and check["has_citation"]:
        citation_ok += 1
    print(f"  {'✓' if check['passed'] and check['has_citation'] else '✗'} 引用  {case['q'][:28]}")

refusal_ok = 0
for question in REFUSAL_CASES:
    result = ask(question)
    answer = result["answer"]
    refused = any(word in answer for word in ("不知道", "没有相关", "无法", "抱歉"))
    if refused:
        refusal_ok += 1
    print(f"  {'✓' if refused else '✗'} 拒答  {question[:28]}")
```

**为什么只测 6 条引用**：每条要调一次 LLM，12 条就是 12 次。
6 条足够看出问题，也省时间。真实项目会全测。

## 如果报错

| 情况 | 原因 |
|---|---|
| 引用大量失败 | 检查 `_normalize` 是否处理了页码 |
| 拒答全部失败 | system prompt 里的拒答规则被删了 |
| Recall 很低 | 向量库不是最新建的，或者 chunks.json 变了 |

## 动手改一处（重要）

**加两条口语化查询**，比如：

```python
{"q": "看病要花多少钱自己先出", "sources": ["sz-medical-insurance-2023.pdf"]},
{"q": "我娃看病挂什么科", "sources": ["lyg-appointment-cancel.pdf"]},
```

重跑，看三种检索的 Recall@3 变化。

**预期**：BM25 会掉下来，向量和混合更稳。

**这一改你要体会到**：**评测集决定你能看到什么。**
如果你的评测集全是关键词查询，你会得出"BM25 就够了"的错误结论。

## 一个真实的坑：拒答题的歧义

我最开始用的拒答题是"你们医院一共有多少张床位"。

结果模型没有拒答——因为语料里有**好几家医院**的简介，
每份都写了床位数。模型拿了其中一家的数字回答。

**这不是模型不听话，是问题本身有歧义**：语料里没有"你们"这个概念。

换成"停车费多少钱一小时"（语料里确实没有）之后，拒答正常。

**教训**：评测用例本身必须是清晰的。**用例写错了，你测出来的是用例的问题，不是系统的问题。**
