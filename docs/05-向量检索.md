## 先理解三件事

### 1. Embedding 是什么

把一段文本变成**一串固定长度的数字**：

```
"退号要收手续费吗"  → [0.023, -0.051, 0.088, ... ]   ← 1024 个数字
"退号收费规则说明"  → [0.021, -0.049, 0.085, ... ]   ← 数值很接近
"今天天气不错"      → [-0.62, 0.014, -0.033, ... ]   ← 数值差很远
```

**关键性质：意思相近的文本，向量也相近。**

那 1024 个数字分别代表什么？**没有人类可读的含义**。
不要试图解释第 37 维是什么——你只需要理解整体性质。

### 2. 余弦相似度

怎么衡量两个向量"近不近"？用它们夹角的余弦：

```
方向一致    → 余弦接近 1  → 很相似
方向垂直    → 余弦接近 0  → 无关
方向相反    → 余弦接近 -1 → 意思相反
```

**为什么用方向不用距离？** 因为向量长度常常和文本长度相关，
我们不希望"一段长文本"仅仅因为长就被认为不相似。

**实现技巧**：先把所有向量归一化（长度变成 1），
那么余弦相似度就等于**点积**，算起来非常快。

### 3. 为什么要分批请求

embedding 是调外部接口。百炼的单次请求有条数上限（20 条）。
一次发 233 条会直接返回 400 错误。

所以按 10 条一批，循环请求。

```python
from src.config import (
    BUILD_DIR,
    DASHSCOPE_API_KEY,
    EMBEDDING_BASE_URL,
    EMBEDDING_MODEL,
)

BATCH_SIZE = 10
```

### 第二步：调用 embedding 接口

```python
def get_client() -> OpenAI:
    return OpenAI(api_key=DASHSCOPE_API_KEY, base_url=EMBEDDING_BASE_URL)


def embed_texts(texts: list[str]) -> np.ndarray:
    client = get_client()
    vectors: list[list[float]] = []

    for start in range(0, len(texts), BATCH_SIZE):
        batch = texts[start:start + BATCH_SIZE]
        resp = client.embeddings.create(model=EMBEDDING_MODEL, input=batch)
        vectors.extend([item.embedding for item in resp.data])
        print(f"  已向量化 {start + len(batch)}/{len(texts)}", end="\r")

    print()
    return np.array(vectors, dtype=np.float32)
```

**注意几点**：

- `base_url` 是百炼的兼容地址，不是 DeepSeek 的
- `resp.data` 的顺序和输入顺序一致，可以直接 `extend`
- 用 `float32` 而不是默认的 `float64`，内存减半

### 第三步：向量索引

```python
class VectorIndex:
    def __init__(self, chunks: list[dict], vectors: np.ndarray):
        if len(chunks) != len(vectors):
            raise ValueError(
                f"块数({len(chunks)})和向量数({len(vectors)})对不上，请重新 --build"
            )
        self.chunks = chunks
        self.vectors = vectors

        norms = np.linalg.norm(vectors, axis=1, keepdims=True)
        norms[norms == 0] = 1.0
        self.normalized = vectors / norms

    def search(self, query: str, k: int = 5) -> list[dict]:
        query_vec = embed_texts([query])[0]
        norm = np.linalg.norm(query_vec) or 1.0
        query_vec = query_vec / norm

        scores = self.normalized @ query_vec
        order = np.argsort(-scores)[:k]

        results = []
        for i in order:
            item = dict(self.chunks[i])
            item["score"] = round(float(scores[i]), 3)
            results.append(item)
        return results
```

**逐段解释**：

- `np.linalg.norm(vectors, axis=1, keepdims=True)` 算出每个向量的长度，
  形状是 `(233, 1)`，可以直接广播相除
- `norms[norms == 0] = 1.0` 防止除以 0
- `self.normalized @ query_vec` 是矩阵乘向量，一次算出所有块的余弦相似度
- `np.argsort(-scores)` 是升序排负数 = 降序排原数

### 第四步：建索引和加载

```python
def build() -> None:
    chunks = json.loads((BUILD_DIR / "chunks.json").read_text(encoding="utf-8"))
    print(f"共 {len(chunks)} 块，开始向量化……")

    vectors = embed_texts([c["text"] for c in chunks])

    np.save(BUILD_DIR / "vectors.npy", vectors)
    print(f"向量维度：{vectors.shape[1]}")
    print(f"已保存：{BUILD_DIR / 'vectors.npy'}")


def load_index() -> VectorIndex:
    chunks = json.loads((BUILD_DIR / "chunks.json").read_text(encoding="utf-8"))
    vectors = np.load(BUILD_DIR / "vectors.npy")
    return VectorIndex(chunks, vectors)
```

### 第五步：入口

```python
def main() -> None:
    if "--build" in sys.argv:
        build()
        return

    args = [a for a in sys.argv[1:] if a != "--build"]
    if args:
        show(" ".join(args))
        return

    print("向量检索。输入 q 退出。")
    while True:
        try:
            query = input("\n查询 > ").strip()
        except (EOFError, KeyboardInterrupt):
            break
        if not query:
            continue
        if query.lower() in {"q", "quit", "exit"}:
            break
        show(query)
```

## 如果报错

| 报错 | 原因 | 解决 |
|---|---|---|
| `401 Unauthorized` | DASHSCOPE_API_KEY 不对 | 检查 .env |
| `400 batch size is invalid` | 一批发太多 | 把 `BATCH_SIZE` 改成 10 或更小 |
| `FileNotFoundError: vectors.npy` | 没跑 `--build` | 先建索引 |
| `块数(233)和向量数(0)对不上` | vectors.npy 损坏 | 删掉重跑 `--build` |

## 动手改一处

把 `BATCH_SIZE` 改成 `1`，删掉 `build/vectors.npy`，重新 `--build`，
用秒表记一下总耗时。

再改回 `10`，重跑，对比。

**预期**：`BATCH_SIZE=1` 要发 233 次请求，明显慢很多。

**这一改你要体会到**：批量不是"优化"，是"能不能用"的问题——
接口有限流，请求次数越多越容易超时。

## 一个必须知道的坑

**换 embedding 模型之后，必须重建整个向量库。**

因为旧向量是用旧模型生成的，新查询向量和新模型在同一个空间，
但和旧向量不在同一个空间。结果：检索**不会报错**，只是安静地变差。

我在 project1 里实测过：换模型后没重建，Recall@1 从 91% 掉到 17%。

**怎么发现**：打印相似度分数。正常是 0.4~0.7，出问题时会接近 0 或负数。
