## 先理解三件事

### 1. 两种检索的失败模式不一样

```
用户问："每个月工资里扣多少医保"
文档写："缴费基数的 8%，个人缴交 2%"

BM25：  找不到 —— "工资""扣" 和 "缴费基数" 没有重合
向量：  找得到 —— 语义相近
```

```
用户问："爽约几次会被限制预约"
文档写："爽约 3 次将暂停预约资格"

BM25：  稳稳找到 —— "爽约" 精确匹配
向量：  也能找到，但可能被其他"预约"相关内容干扰
```

**一个强在精确词，一个强在语义。合起来互相补位。**

### 2. 为什么不能把分数直接相加

两路的分数量纲完全不同：

| 检索方式 | 分数范围 |
|---|---|
| 向量 | 余弦相似度，0~1 |
| BM25 | 词频统计得分，0 到几十，没有上界 |

给 0.6 的向量分和 12.3 的 BM25 分加权求和，等于拿"米"和"公斤"相加。

### 3. RRF：只看名次

Reciprocal Rank Fusion 的公式：

```
某块的总分 = Σ  1 / (k + 它在某一路里的名次)

k 一般取 60
```

举例：

```
块 A：向量排第 1，BM25 排第 3
     = 1/(60+1) + 1/(60+3) = 0.0164 + 0.0159 = 0.0323

块 B：向量排第 5，BM25 排第 1
     = 1/(60+5) + 1/(60+1) = 0.0154 + 0.0164 = 0.0318

→ A 略高于 B
```

**名次是无量纲的**，两路可以比。这就是 RRF 绕开量纲问题的办法。

**分母为什么加 60？** 平滑。不加的话第 1 名得分 1，第 2 名 0.5，
差距太大，一路的第 1 名会压倒性主导结果。

### 第二步：RRF

```python
def rrf_fuse(ranked_lists: list[list[dict]], k: int = 60, top: int = 5) -> list[dict]:
    scores: dict[str, float] = {}
    by_id: dict[str, dict] = {}

    for results in ranked_lists:
        for rank, item in enumerate(results, 1):
            chunk_id = item["id"]
            by_id.setdefault(chunk_id, item)
            scores[chunk_id] = scores.get(chunk_id, 0.0) + 1.0 / (k + rank)

    order = sorted(scores, key=lambda cid: scores[cid], reverse=True)[:top]
    return [{**by_id[cid], "rrf": round(scores[cid], 5)} for cid in order]
```

**逐段解释**：

- `ranked_lists` 是多个有序列表，比如 `[bm25结果, 向量结果]`
- `enumerate(results, 1)` 让名次从 1 开始
- `scores.get(cid, 0.0) + ...` 表示同一块在两路里都出现时，分数累加
- `by_id.setdefault` 只保留第一次见到的块内容（两路返回的块是同一份）
- `{**by_id[cid], "rrf": ...}` 把原块和 RRF 分数合并成一个新字典

### 第三步：索引缓存

```python
_bm25 = None
_vector = None


def _indexes():
    global _bm25, _vector
    if _bm25 is None:
        _bm25 = load_bm25()
        _vector = load_vector()
    return _bm25, _vector
```

**为什么要缓存**：BM25 建索引要分词 233 个块，向量加载要读 npy。
每次查询都重建的话，评测跑 12 条就会慢很多。

**这就是"索引只建一次"的具体实现。**

### 第四步：检索

```python
def search(query: str, top: int = 5, candidate: int = 15) -> list[dict]:
    bm25, vector = _indexes()

    return rrf_fuse(
        [bm25.search(query, candidate), vector.search(query, candidate)],
        top=top,
    )
```

**`candidate=15` 是什么**：每一路先各取 15 个候选，再融合成 top 5。

**为什么要多取**：如果两路都只取 5 个，那么融合只能在 10 个候选里选，
很多本来排第 8 但两路都出现的块就进不来——而"两路都出现"恰恰是强信号。

### 第五步：入口

```python
def show(query: str, top: int = 5) -> None:
    print(f"\n查询：{query}\n")
    for rank, item in enumerate(search(query, top), 1):
        preview = " ".join(item["text"].split())[:90]
        print(f"  {rank}. [{item['source']} 第{item['page']}页] RRF {item['rrf']}")
        print(f"     {preview}…")


def main() -> None:
    if len(sys.argv) > 1:
        show(" ".join(sys.argv[1:]))
        return
    # 交互模式略，和上一课一样
```

## 动手改一处

把 `candidate` 从 15 改成 5，重跑同一个查询，对比结果。

再改成 30，对比。

**观察**：候选越多，融合能考虑的范围越大，但噪音也越多。
`top 5` 里可能出现原本排第 20 的块。

**这一改你要体会到**：RRF 的效果依赖两路各自召回的质量。
如果某一路前 15 个全是垃圾，融合也救不回来。

## 一个诚实的观察

在本项目的评测集上，混合检索和 BM25 的 Recall@3 都是 100%，
向量是 92%。

**这不是说混合没用**，而是说：**这份评测集以关键词查询为主**，
BM25 本来就擅长。想看出向量的价值，你需要加"口语化改写"的查询。
