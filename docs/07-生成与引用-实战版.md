## 先直接回答你的问题

你问："还没制定 LLM 提示词说资料没有的就拒绝回答而不是瞎造吗？"

**制定了，而且不只靠提示词。** 现在的做法是三层：

| 层 | 做什么 | 代码位置 |
|---|---|---|
| 1. 检索层 | 先保证一定有资料送进去；一条都没检索到就直接拒答 | `ask()` 开头 |
| 2. 提示词 | 明确规则：资料里没有就只回复"资料里没有提到这个问题"；有答案必须用 `[编号]` 标注出处 | `SYSTEM_PROMPT` |
| 3. 代码校验 | 检查回答有没有 `[编号]`、编号是不是真的存在；不合规重试一次，仍不合规就降级为拒答 | `check_answer()` |

为什么不能只写 prompt？因为 prompt 是自然语言，是"建议"，模型可以选择忽略。
代码校验才是"规则"：它能把"有没有编出处"从人工判断变成自动判分。

## 一、提示词原文

```python
SYSTEM_PROMPT = """你是《高性价比人生指南》的问答助手。你只能依据【资料】回答，不能使用你自己的知识。

硬性规则：
1. 先判断【资料】里有没有回答问题所需的信息。
2. 如果资料里没有，只回复一句：「资料里没有提到这个问题。」不要猜，不要补充常识，不要编数字、法条或出处。
3. 如果资料只回答了一部分，先回答资料里有的部分，再明确说「资料里没有提到……」，不要补全。
4. 如果资料里有答案：用资料里的原话和数字回答，每个关键结论后面用 [编号] 标注出处，例如 [1][3]。
5. 只能引用资料里出现过的编号，不能编造编号。
6. 不要给资料之外的医疗、法律、投资建议。
7. 中文回答，先结论后细节，尽量简短。"""
```

每条规则都对应一个具体失败模式：

| 规则 | 防止的问题 |
|---|---|
| 1、2 | 资料里没有，模型用自己的常识补一个答案 |
| 3 | 资料只答了一半，模型把另一半也"补全" |
| 4 | 回答正确但无法追溯，用户不知道依据在哪 |
| 5 | 编造 `[9]` 这种不存在的编号 |
| 6 | 医疗/法律/投资问题给出危险的自创建议 |
| 7 | 回答太长，把检索到的无关内容也复述一遍 |

**规则 3 是这次实测里最微妙的一条。** "深圳医保住院起付线是多少"：
资料里有"住院起付线接着算"这句话，但没有给具体金额。
模型选择了整体拒答，而不是"资料提到起付线但没给数字"。
这偏保守，但没有编数字——对 RAG 来说，**宁可少说，不可编造**。

## 二、代码怎么读

打开 `src/rag_answer.py`。

### 1. 拼资料：每条带编号、节条号、页码

```python
def build_context(hits: list[dict]) -> str:
    parts = []
    for i, hit in enumerate(hits, 1):
        parts.append(f"[{i}] {position_of(hit)} | 第 {hit['page']} 页\n{hit['text']}")
    return "\n\n".join(parts)
```

送给模型的内容长这样：

```
[1] 第 5 节第 14 条 | 第 117 页
【5. 不要浪费钱】
14. 喝烧开的自来水，不常年订饮水机用的桶装水、买瓶装水
• 成本：……

[2] 第 13 节第 13 条 | 第 307 页
……
```

编号 `[1]` 是模型回答时唯一允许使用的引用方式。
节条号和页码既帮模型定位，也方便你人工核对。

### 2. 引用提取

```python
CITE_RE = re.compile(r"[\[【]\s*(\d+(?:\s*[,，、]\s*\d+)*)\s*[\]】]")
```

能识别 `[1]`、`【1】`、`[1,3]`、`[1，3]`、`[1、3]`。
提取后去重，再检查每个编号是否落在 `1..len(hits)` 里。

```python
valid = [n for n in cited if 1 <= n <= len(hits)]
invalid = [n for n in cited if not (1 <= n <= len(hits))]
```

### 3. 拒答识别

```python
REFUSAL_RE = re.compile(r"(资料|材料|书中|本文).{0,12}(没有|未|找不到|不涉及|没提)|无法回答|不能回答")
```

注意判断条件：

```python
refused = bool(REFUSAL_RE.search(answer)) and not valid
```

只有"说了没有 + 没引用任何有效编号"才算完整拒答。
如果回答是"资料里没有具体金额，但提到……[1]"，那就是**部分回答**，不算拒答。

### 4. 状态机

```python
if valid:
    status = "answered"      # 有有效引用：通过
elif refused:
    status = "refused"       # 明确说没有：拒答
else:
    status = "unverified"    # 既没引用也没拒答：可疑
```

`unverified` 的处理：

```
第一次回答 → 没有引用、也没拒答
    ↓
把上一次回答和"请按规则重新回答"追加到消息里
    ↓
再问一次
    ↓
仍然 unverified → 用兜底话术替换，状态 blocked
```

兜底话术：

```python
FALLBACK_ANSWER = "资料里没有找到可以核实的依据，无法回答这个问题。"
```

### 5. 接口内容审核的兜底

实测时踩到一个真实的坑：

```
400 data_inspection_failed
Input text data may contain inappropriate content.
```

同一个问题，`deepseek-v4.1-flash` 被拦截，`deepseek-v4.1-flash-1017` 正常。
所以代码把这种情况单独接住，返回一句可读提示，而不是直接抛异常：

```python
except BadRequestError as exc:
    if "data_inspection_failed" in str(exc):
        return {..., "check": {..., "status": "api_blocked"}}
    raise
```

这是外部接口边界才需要的处理，不要给每个内部函数都套 try/except。

### 6. 输出里保留检索结果

```
检索到 5 条：
  [1] 第 5 节第 14 条 | 第 117 页 | 14. 喝烧开的自来水……
  [2] 第 13 节第 13 条 | 第 307 页 | 13. 被狗、猫咬伤……
```

**为什么要把没被引用的条目也列出来？**
为了让你看到检索的噪声。第 1 名很准，第 2–5 名可能完全无关；
这些无关条目会占用 prompt 的 token，也会增加模型被带偏的机会。
第 8 课会量化"检索噪声对回答质量的影响"。

## 四、四个实验（必须动手）

### 实验 A：完全不给资料

把 `ask()` 里的 `hits` 强制改成空列表，或者直接问一个没有检索结果的问题，
观察模型会不会用自己的知识回答。

**实测**：直接问模型"红烧肉怎么做"（不带任何资料），它会给出完整的配料和步骤。
问"这本书的作者是谁"，它会说无法确认。

**要体会**：模型本身知道很多事。RAG 的护栏不是"让模型变笨"，
而是**保证它回答时手里有资料、并且答案能追溯到资料**。
如果检索层返回空，代码会直接拒答，不会把问题裸送给模型——
这就是第一层防线。

### 实验 B：删掉提示词里的拒答规则

把规则 1、2 删掉，只保留"依据资料回答"。

**实测**：在这份数据和这个模型上，它仍然会拒答"红烧肉怎么做"，
因为检索到的资料明显不相关。

**这说明什么**：不能把"模型没编"当成"prompt 有效"的证据。
模型这次听话，不代表换个模型、换个问法还听话。
提示词的价值是**让行为可预期、可评测**，不是"唯一防线"。

### 实验 C：关掉代码校验

把 `check_answer()` 的 `status` 判断改成永远 `answered`，或者不重试。

**预期**：大部分回答仍然有 `[1]`，但偶尔会出现没有编号的回答，
或者 `[9]` 这种不存在的编号，而系统不会提示你。

**要体会**：没有校验，你根本不知道它有没有编。
这就是"能演示"和"能上线"的区别。

### 实验 D：`--top 1` 和 `--top 10`

```powershell
.\.venv\Scripts\python.exe src\rag_answer.py --top 1 "被公司裁了赔偿金怎么算"
.\.venv\Scripts\python.exe src\rag_answer.py --top 10 "被公司裁了赔偿金怎么算"
```

**预期**：`top 1` 时答案更短、可能漏掉"2N"和"多一个月工资"；
`top 10` 时资料更全，但无关条目也更多，模型更容易把噪声写进答案。

**这一改你要体会到**：top_k 不只是检索参数，它直接决定模型能看到多少上下文。

## 五、这次踩到的真实坑

| 现象 | 原因 | 处理 |
|---|---|---|
| `404 Model not exist` | `.env` 没设 `MODEL`，config 默认的 `deepseek-v4-flash` 在这套接口上不存在 | 换成 `deepseek-v4.1-flash-1017` |
| `400 data_inspection_failed` | `deepseek-v4.1-flash` 对"裁员赔偿"这段资料触发内容审核 | 换 `-1017` 快照；代码里单独接住该错误 |
| `403 Free quota exhausted` | 试了 `qwen3.7-plus`，免费额度用尽 | 不要混用没有额度的模型 |
| 回答里没有 `[编号]` | 模型没遵守格式 | 重试一次；仍不合规就降级拒答 |

**模型名是环境的一部分。** 换接口、换模型之后，这 8 条验收必须重跑一遍。

## 六、已知限制

1. **引用编号有效 ≠ 结论正确**。模型可能引用了 `[1]`，但把 210 倍记成 120 倍。
   校验器只检查"编号存在"，不检查"数字抄对没有"。
2. **模型可能引用正确编号但断章取义**。比如资料说"某类人收益小"，模型说成"所有人收益小"。
   这需要第 8 课的 LLM-as-judge 或人工抽查来发现。
3. **拒答可能过度保守**。"深圳起付线"那条，资料有相关条目但没数字，模型整体拒答。
   要让它给出"资料提到 X，但没给具体金额"的部分回答，需要更细的 prompt 或 few-shot。
4. **prompt 仍是软约束**。模型可以忽略；重试只能兜底格式，兜底不了事实。
5. **内容审核会误伤**。合法的法律/医疗段落也可能被接口拦下。
6. **temperature=0 不等于完全可复现**。不同模型版本、不同接口的同一模型，输出仍可能变。

## 七、下一步：第 8 课评测

现在"会不会瞎造"还是靠人工看 8 条。第 8 课要把它变成数字：

| 指标 | 怎么算 |
|---|---|
| 检索 Recall@3 | 标准答案的 `(节号, 条号)` 在不在前 3 条里 |
| 引用有效率 | 回答里的 `[n]` 是否都能对应到本次检索结果 |
| 拒答正确率 | 资料外的问题有没有拒答；资料内的问题有没有被误拒 |
| 回答正确率 | LLM-as-judge 或人工，按标准答案打分 |

评测集就从今天这 8 条开始扩到 20–30 条，每条标：

- 问题
- 类型：资料内 / 资料外 / 部分覆盖
- 标准答案（或"应拒答"）
- 可接受的检索条目

有了这张表，你才能回答："把混合检索的权重从 1:3 改成 1:5，答案正确率是涨了还是跌了？"
